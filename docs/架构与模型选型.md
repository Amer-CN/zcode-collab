# 协作模式：架构与模型选型说明（2026-09-12）

> 给群友的一句话：这套席位表不是拍脑袋排的，是 2026-09-12 一下午用三轮独立调研（共约 270 次工具调用取证）+ 两次本地实测推出来的。每个位置为什么是它、为什么不是别人，下面都有数字和出处。

## 一、协作模式架构的调整：为什么选择这个架构

### 1.1 骨架：主模型编排 → 执行 → 跨厂商独立审查

```
用户需求
  ├─ A类（现成方案）→ 跳过出方案，直接执行
  ├─ B类（大白话需求，走完整四步）→ 出方案 → 写简报 → executor干活 → code-reviewer审查 → 裁决
  ├─ C类（纯讨论问答）→ 直接回答
  └─ D类（≤2文件小改）→ 直接做
        ↓
  简报（.work/current-task.md 或 task-*.md）：基线提交 + 允许/禁止文件 + 可验证的验收标准
        ↓
  钩子强制执行：PreToolUse拦截未申报写入、Stop拦截无简报施工、PostToolUse写审计日志
```

为什么这样定：

- **执行席的编码上限被简报锁死**：executor手里有简报，改哪个文件、改哪几行、怎么验收全写死了，聪明用不上，值钱的是纪律（不越界）+吞吐。所以执行席不需要最聪明的模型，需要最听话、最快、最便宜的。
- **审查席是全系统唯一错不过去的闸门**：executor干错了审查能拦，审查漏了错误直接进仓库。所以审查席要全场看代码眼力最强的模型。
- **审查者必须和主模型、执行者不同权重**：同一份权重自审，盲区100%重合，等于没审。所以主/执/审三席必须三家厂商，零重叠。这是铁律。
- **圆桌（advisor-A/B/C）必须是三家不同厂商**：配成同一家，圆桌变复读机。圆桌吃的是通识和判断，不吃动手能力。
- **高频席位只给快的，深度红利留给低频席位**：主模型、执行是每轮都等的位置；圆桌、深度调研是偶发的，等得起。所以"慢而深"的模型只进圆桌，不进常驻循环席。
- **偏科模型放在岗位边界挡得住短板的位置**：审查章程只管"做对了没有"，不管"该不该做"，通识短板被挡在外面。

## 二、模型选型依据：每个位置为什么是它

### 2.1 总表：四个硬维度同台对比（独立来源）

解读：

- **muse**：综合、指令遵循、知识、编码四个硬维度全部第一，是全池最强。短板是官方API首字慢（AA测20秒，见2.4节），但在opencode渠道实测不慢。
- **DeepSeek**：执行/agent类四源一致最强（LiveBench agentic coding 77.3对GLM满血60.9；ReLE编码65.0对58.0；AA-AutomationBench 68.9对62.2），速度最快（官方217 t/s），最便宜。但裸知识弱（HLE 39.1）。
- **GLM-5.3**：综合大脑AA类内第一，中文已测且强（ReLE总分#10、语言与指令遵从域#6、LMArena人类偏好#15）。短板是官方口径慢（62 t/s），但在团结渠道实测极快（见2.4节）。
- **GLM-5.3-Flash**：小杯，TB 2.1三方一致84.3，调研/识图够用；但肚里货薄（Omniscience 7.47，只有大哥一半），不够格上圆桌。

### 2.2 主模型为什么是 muse-spark-1.3

主席岗位的真正考核项是：指令遵循（听不听治理文档的话）、综合处理、肚里货。每一项都有实测，muse全部第一：LiveBench IF 78.0对69.3（差8.7分，这是主席核心竞争力的最直接测量）、总分82.4对76.1、HLE 47.5对42.3。

GLM-5.3手里剩两张牌：中文已测（muse中文零榜覆盖，这是唯一暗区，裁判是用户自己的手感——圆桌里读过的就是muse写的中文）、团结渠道快。但速度那张牌98～200 t/s对聊天主席绰绰有余，不构成翻盘。

厂商：Meta官方模型（2026-09-02发布），"-contributor"是官方折扣档（把prompts/completions给Meta训练换超低价），不是中转商改名。多家转售（OpenRouter、bothub、opencode Zen/Go）原样使用该名。推理档共5档minimal/low/medium/high/xhigh，xhigh即满血（max在API上不存在，Meta官方wire只到high，xhigh映射high——2026-09-11实测证实）。

### 2.3 执行席为什么是 DeepSeek V4.1-Flash

全场唯一有实测数据的指派，画像就是"长程执行"：官方表Terminal-Bench 2.1得90.6、DeepSWE 74.2（全表第一），四个独立来源全说它执行更强（幅度最大的一项agentic coding差16个点）。1M上下文扛长循环，原生视觉（执行中途能自己看截图验收），官方217 tokens/s，缓存命中$0.003（执行体反复回读上下文几乎不要钱；HN实测447轮长任务$0.62对比GPT-6-astra $55）。

注意：TB2.1的90.6、DeepSWE的74.2等最响的几行至今无独立复测（模型2026-09-10才发布两天，AA编码分还是null，LMArena未收录，官方榜无DeepSeek提交）。执行力有数据，"不越界、不自作主张"无数据——这是整板唯一无数据的关键变量，两周实测盯的就是它。

### 2.4 速度争议：两次"官方很慢、渠道很快"的实测

- **muse**：AA在Meta第一方API上测首字20.5秒（~1万token重请求+顶格推理档，且Meta把思考内容加密隐藏，直连要等29.5秒才见可读字）。但OpenRouter 7.7万真实请求中位总往返仅2.6秒、中位吞吐98 t/s；同走OpenCode Go的用户原话"the thing flies, 200+ tok/s"。结论：AA数字是真的，但是窄口径（只代表第一方API）；用户渠道体感快有数据支撑。
- **GLM-5.3**：AA在智谱官方API上62 t/s、首字3.16秒。但2026-09-12直接打本机团结通道（127.0.0.1:8788的codely-core=GLM-5.3）实测：首字1.3～1.6秒，吐字512～687 t/s（三次采样），是AA官方数的10倍、同管道DeepSeek-V4-Flash的3～4倍。结论："GLM-5.3慢"条款实测撤销。

### 2.5 主模型为什么走Go付费档、不走Zen免费档

两档是同一模型（同快照2026-09-02、同5档推理档位、数据条款逐字相同），全网无同场延迟实测，谁吐字更快没有数据。区别只在可用性的可预测性：

- 免费档：官方无额度数字，"for a limited time"随时可撤；429真实存在（有首个请求即429的案例）；第三方逆向共识是按出口IP共享促销池——墙什么时候倒取决于同IP还有谁在用。
- Go档（$10/月）：每月$60美元额度（官方估算45300次/5h），超限拦截或回退，不排队不降速；每天几十轮对话只占很小比例；口碑"flies, a pleasure to use"。

主模型是全系统最高频席位，吃不起随机429。结论：主席走Go，免费档留作熔断备胎。官方从未说过"Go高并发、免费限并发"——两档都没公布过并发数，这是额度模型不同造成的现实效果，不是QoS承诺。

### 2.6 中文指令遵从争议：11.4分差距是纸糊的

ReLE"中文指令遵从"分榜DS 51.4对GLM-5.3 40.0（差11.4）经查不可用：它是两次孤立单发测量之差（DS是2026-09-12首测日第一个数据点，GLM是08-23测的之后从未复测），题量仅约35个计分单元，同榜同族不同快照能差20分，且ReLE自家宽口径域榜方向直接反转（GLM-5.3 75.0＞DS 74.1）。唯一覆盖三候选、客观判分、可复核的IF测量是LiveBench英文IF：DS 70.0、GLM-5.3 69.3（打平），muse 78.0最高。中文IF轴定性：单源、单发、小样本、自相矛盾，不足为凭。此前的"DS靠中文纪律坐主席"论据正式作废。

## 三、模型职责与适用场景

| 模型 | 岗位 | 应该干什么 | 适合干什么 | 不适合干什么 |
|---|---|---|---|---|
| muse-spark-1.3 (xhigh) | 主模型（+圆桌讨论时可参考） | 出方案、写简报、编排子智能体、裁决、写中文汇报 | 综合判断、指令遵循、看图（原生视觉）、编码 | 放在没有数据条款确认的绝密项目（contributor档数据进Meta训练池；本机项目已确认不介意） |
| DeepSeek V4.1-Flash | executor执行 | 按简报机械施工：改代码、跑验证命令、回读文件 | 长程多轮执行、反复读上下文、高吞吐 | 出开放式方案（世界知识弱HLE 39.1）、当无网裁判（动手偏科生） |
| GLM-5.3 完整版 | code-reviewer审查 + advisor-B圆桌 | 对照简报挑错（只管做对了没有）；圆桌给判断 | 代码审查、通识判断、中文任务 | 高频交互（官方口径慢；团结渠道实测快，可结合渠道看） |
| GLM-5.3-Flash | researcher调研 + vision-reader识图 | 联网查资料、跑几十轮工具循环取证；图片描述 | 调研取证（GDPval 1674、TB三方一致84.3）、识图（原生多模态，LiveBench vision 60.3） | 圆桌判断（肚里货只有大哥一半）、竞赛式算法题（LiveCodeBench #58） |
| K3 | advisor-A圆桌 | 给"该不该做/选哪个"类决策出判断 | 通识、长上下文（HLE 43.5全场最高） | 常驻循环席（渠道限速解除前不进） |
| Qwen3.8-Max | advisor-C圆桌 | 同上 | 深度判断 | 常驻循环席（又贵又慢，只在圆桌偶尔用） |
| Qwen3.8-Flash | 板凳 | 轮换C席，给表现机会 | 同上（弱一档） | 与Max并排上桌（圆桌三席必须三家厂商） |

使用提醒：

1. 慢模型（K3、两款Qwen）限速解除前只进圆桌这种"单发席位"，不进调研/执行/审查这类"循环席位"——限速在多轮工具循环里会被放大几十倍。
2. GLM-5.3-Flash默认max推理档会"过度探索、迟迟不交付"（第三方实测medium+输出上限反而更好），嫌调研员啰嗦时给它设输出上限。
3. 承诺窗口：两周或10个真实任务内整板别动，盯四个信号——放权率（子智能体调用数÷任务数）、审查驳回率5～20%、主席漏判协作模式次数、汇报长度。反转条件：muse中文/治理别扭→回GLM主席板；GLM-5.3审查连续10次零驳回→先查简报质量；DS执行越界→换回GLM-Flash执行。
